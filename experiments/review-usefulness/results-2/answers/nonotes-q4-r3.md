The library's `llm/memory/` folder (70 papers) sorts agent memory systems into about seven families. They differ on four things: where the memory lives, what it holds, how it is organised, and who decides what gets written, updated and deleted.

I read the surveys and the comparison studies closely; the one-line descriptions of individual systems come from the library's summaries and section headings, not a full read of each paper.

## A running example

A user says "I live in Berlin" in January and "I've moved to Lisbon" in March. In June they ask "what's a good café near me?" Each family handles this differently:

| Family | What it stores | What happens to "Berlin" | Examples |
|---|---|---|---|
| **Flat extract-and-retrieve** | Short facts pulled out by an LLM, embedded in a vector store | An LLM picks add, update, delete or no-op per new fact; whether Berlin gets overwritten depends on that call | [Mem0, p. 3](http://pdf.invalid/llm/memory/agent/Mem0.%20Building%20Production-Ready%20AI%20Agents%20with%20Scalable%20Long-Term%20Memory.pdf?dest=subsection.2.1&page=3), SeCom, LightMem |
| **Stream plus reflection** | A timestamped log of everything, plus periodic higher-level summaries written back into it | Both facts stay; retrieval scored by recency, importance and relevance should favour Lisbon | [Generative Agents, p. 8](http://pdf.invalid/llm/memory/agent/Generative%20Agents.%20Interactive%20Simulacra%20of%20Human%20Behavior.pdf?dest=subsection.4.1&page=8), MemoryBank (adds decay) |
| **Tiered, OS-style** | A small always-in-context core plus searchable archives, with paging between them | The model itself edits "location: Berlin" in core memory through a tool call | [MemGPT, p. 2](http://pdf.invalid/llm/memory/agent/MemGPT.%20Towards%20LLMs%20as%20Operating%20Systems.pdf?dest=section.2&page=2), [MemoryOS, p. 3](http://pdf.invalid/llm/memory/agent/Memory%20OS%20of%20AI%20Agent.pdf?dest=section.3&page=3), MemOS |
| **Graph** | Entities and relations, often with validity times | The "lives in Berlin" edge is marked invalid from March rather than deleted, so "where did I live in February?" still works | [Zep, p. 2](http://pdf.invalid/llm/memory/agent/Zep.%20A%20Temporal%20Knowledge%20Graph%20Architecture%20for%20Agent%20Memory.pdf?dest=section.2&page=2), Mem0's graph variant, HippoRAG, [A-MEM, p. 3](http://pdf.invalid/llm/memory/agent/A-MEM.%20Agentic%20Memory%20for%20LLM%20Agents.pdf?dest=section.3&page=3) (linked notes) |
| **Typed stores** | Separate stores per kind of memory (core, episodic, semantic, procedural and so on) | Routed to a profile or semantic store with its own conflict rules | [MIRIX, p. 6](http://pdf.invalid/llm/memory/agent/MIRIX.%20Multi-Agent%20Memory%20System%20for%20LLM-Based%20Agents.pdf?dest=subsection.3.1&page=6), Memanto (argues typing makes graphs unnecessary) |
| **Experiential / procedural** | Lessons, strategies and workflows distilled from past task runs, not facts about the user | Not applicable: it remembers how to do things, not what is true | ExpeL, [Agent Workflow Memory, p. 3](http://pdf.invalid/llm/memory/agent/Agent%20Workflow%20Memory.pdf?dest=subsection.2.3&page=3), [ReasoningBank, p. 4](http://pdf.invalid/llm/memory/agent/ReasoningBank.%20Scaling%20Agent%20Self-Evolving%20with%20Reasoning%20Memory.pdf?dest=subsection.3.2&page=4), Dynamic Cheatsheet, Memp |
| **Parametric / latent** | Weights, adapters, memory vectors or KV caches | The fact is edited or trained in; there is no record to inspect or delete | MemoryLLM, M+, Titans, Cartridges, MEMIT (`llm/memory/parametric/`) |

## The four axes behind the families

- **Where it lives.** [Memory in the Age of AI Agents, p. 12](http://pdf.invalid/llm/memory/agent/Memory%20in%20the%20Age%20of%20AI%20Agents.pdf?dest=section.3&page=12) splits this into token-level (text in a store), parametric (weights) and latent (hidden states or KV caches). Text is inspectable and deletable; the other two are compact but opaque.
- **What it is for.** The same survey separates factual, experiential and working memory ([p. 31](http://pdf.invalid/llm/memory/agent/Memory%20in%20the%20Age%20of%20AI%20Agents.pdf?dest=section.4&page=31)). Others use the cognitive labels: episodic (what happened), semantic (what is true), procedural (how to do it).
- **How it is organised.** Flat sequence, graph or tree, or composite objects carrying text plus metadata ([Are We Ready, p. 4](http://pdf.invalid/llm/memory/agent/Are%20We%20Ready%20For%20An%20Agent-Native%20Memory%20System.pdf?dest=subsubsection.3.1.1&page=4)).
- **Who controls it.** This is the least discussed axis and arguably the most consequential ([Memory for Autonomous LLM Agents, p. 3](http://pdf.invalid/llm/memory/agent/Memory%20for%20Autonomous%20LLM%20Agents%20Mechanisms,%20Evaluation,%20and%20Emerging%20Frontiers.pdf?dest=subsection.3.3&page=3)):
  - Heuristic rules, such as top-k retrieval or summarising every n turns.
  - Prompted self-control, where the LLM calls memory tools (MemGPT).
  - Learned control, where memory operations are trained with RL ([Memory-R1, p. 3](http://pdf.invalid/llm/memory/agent/Memory-R1.%20Enhancing%20Large%20Language%20Model%20Agents%20to%20Manage%20and%20Utilize%20Memories%20via%20Reinforcement.pdf?dest=subsection.3.1&page=3), Mem-α, MemAgent).

## How they differ in practice

The head-to-head studies matter more than the individual system papers, which mostly report their own wins on LoCoMo.

- **No architecture wins everywhere.** Across 12 systems and 11 datasets, composite hybrids lead on conversational QA, while graphs are best at single-hop recall and at knowledge updates but weak on temporal reasoning ([Are We Ready, p. 2](http://pdf.invalid/llm/memory/agent/Are%20We%20Ready%20For%20An%20Agent-Native%20Memory%20System.pdf?page=2&search=No%20single%20memory%20architecture)).
- **Structure is expensive.** Zep and Cognee reach the top utility scores only at 155 s and 117 s of amortised latency per query, against 3.7 s for LightMem. Mem0 scores 21.4 normalised utility at 35.9 s, well below its own paper's framing ([Are We Ready, p. 10](http://pdf.invalid/llm/memory/agent/Are%20We%20Ready%20For%20An%20Agent-Native%20Memory%20System.pdf?dest=subsection.4.5&page=10)). The cost driver is how widely each write propagates, not whether there is a graph.
- **Every abstraction layer loses information.** Summaries and extracted facts drop chronological cues, so for time-dependent questions the raw long context still beats most memory systems (same paper, p. 2). EvoMemBench finds the same across 15 methods: long-context baselines stay highly competitive ([p. 6](http://pdf.invalid/llm/memory/benchmarks/EvoMemBench.%20Benchmarking%20Agent%20Memory%20from%20a%20Self-Evolving%20Perspective.pdf?page=6&search=Strong%20long-context%20baselines)).
- **Forgetting is a separate capability from recall.** One verbatim-retention store scores 40% on a recall benchmark and 0 of 385 on adversarial deletion ([Control-Plane Placement, p. 6](http://pdf.invalid/llm/memory/agent/Control-Plane%20Placement%20Shapes%20Forgetting.%20An%20Architectural%20Study%20of%20Agent%20Memory%20Across%20Thirteen.pdf?dest=subsection.5.5&page=6)). An LLM at write time fixes canonicalisation ("NYC" versus "New York") but not intent-aware deletion; an LLM at mutation time fixes the reverse ([p. 8](http://pdf.invalid/llm/memory/agent/Control-Plane%20Placement%20Shapes%20Forgetting.%20An%20Architectural%20Study%20of%20Agent%20Memory%20Across%20Thirteen.pdf?dest=subsection.5.7&page=8)).
- **Fact memory and experience memory serve different tasks.** Retrieval-based methods stay strong on knowledge-heavy settings; procedural memory helps on execution tasks only when stored experience matches the task structure (EvoMemBench, abstract, p. 1).

## What to treat with caution

- **AgentMemBench** claims a plain key-value store beats graphs and summaries on every axis ([p. 1](http://pdf.invalid/llm/memory/benchmarks/AgentMemBench.%20A%20Systematic%20Benchmark%20for%20Evaluating%20Long-Term%20Memory%20Management%20Strategies%20in.pdf?page=1)). It rests on 491 questions, a 4-bit 7B model and a best answer F1 of 0.156, and it contradicts the larger study on graphs, so I would not lean on it.
- **The forgetting study** is written by the vendor of one of the systems it evaluates (Lethe), and its 0/385 system has no deletion primitive by design. The placement argument is interesting; the rankings are not independent.
- **The 2023 systems** (Generative Agents, MemGPT, MemoryBank) were designed for 8k-token contexts. Their mechanisms (reflection, paging, decay) survive in later systems, but their motivating constraint is largely gone, which is why long-context baselines now hold up so well.
- **LoCoMo results** in system papers are weak evidence: the Memory for Autonomous LLM Agents survey reports that models near saturation on LoCoMo drop to 40–60% on MemoryArena (p. 4, Table 1).
