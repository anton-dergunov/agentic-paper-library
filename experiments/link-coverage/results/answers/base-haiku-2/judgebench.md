**Short answer:** read pages 4–6 closely, then the Table 4 and Figure 4 ablation on page 10. Everything else can be skimmed.

**Read in this order**

1. **Pp. 4–5, Figure 2 and Section 3 ("JudgeBench's pipeline").** This is the construction. Sample k responses from one strong model (GPT-4o), grade each for correctness against ground truth, keep only questions where the samples disagree, and pair a correct response with an incorrect one. The key idea is that a model inconsistent on a question is also one that can't tell right from wrong on it.
2. **P. 5–6, "Datasets" and "Data filtering".** Four sources: MMLU-Pro (knowledge), LiveBench (reasoning and math), LiveCodeBench (coding). Responses that GPT-4o-mini and the automatic checker disagree on are dropped as format errors. Final size is 350 pairs (154 / 98 / 56 / 42).
3. **P. 6, Section 4 "Evaluation".** Each pair is judged twice with the order swapped. A pair counts as correct only if both verdicts agree on the right answer, or one is right and the other a tie. Inconsistent or double-tie verdicts count as wrong. This rule decides what every number means, so read it before the tables.
4. **P. 9–10, Section 4.4 and Table 4 / Figure 4.** Two checks: judging versus solving the same problem, and the same pairs generated by Claude instead of GPT-4o. The second is the main caveat: Claude's judge falls from 64.3% to 44.8% on Claude-generated pairs. The note's Digest explains why this is a selection effect and why the paper's "single generator removes self-preference" argument still holds.

**Skim as needed**

- **Pp. 1–2:** the argument that crowd preference is the wrong target for hard questions. Read the intro for motivation only.
- **Pp. 7–8, Tables 1–3:** the results. Look at the reasoning-model gap (o3-mini high at 80.86% against GPT-4o at 56.57%) and the reward-model band (59–64%). Check the table cells you need rather than memorising them.
- **P. 9, Figure 3:** how other meta-benchmarks compare. Useful for the "JudgeBench is harder" claim.
- **Appendix A.3 (p. 19):** how the random filtering balances subsets.
- **Appendix A.4 (p. 20):** length bias. Relevant if you care about the "judges prefer longer answers" point.
- **Appendix A.5 (p. 20):** an example where the two correctness checks disagree.
- **Appendix A.6 (p. 21):** the judge prompts. Read these only if you want to reproduce.
- **Appendix A.1–A.2 (pp. 16–18):** judge details and fine-tuned-judge analysis. Skip unless you need them.
- **Related work, p. 2–3:** skip.

**Most useful overall**

- **Pipeline plus scoring rule (pp. 4–6).** Once you have these, you can judge any similar benchmark and see what its numbers mean.
- **The generator ablation (p. 10, Figure 4).** It shows the benchmark's limits: the questions were chosen because one model is unstable on them, so absolute numbers are not general judge accuracy.

**One check I did while reading**

Under the swap-and-agree rule, a judge that flips a coin on each trial gets a correct verdict about 25% of the time, not 50%, because both trials must agree on the right answer. The paper's "random guessing" comparison on p. 8 is therefore generous. This is my arithmetic, not a figure the paper reports, but it matches the note's point that the rule penalises guessing.
