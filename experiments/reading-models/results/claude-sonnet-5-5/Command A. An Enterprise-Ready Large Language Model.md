## Digest

- Pipeline: a decoder-only Transformer with SwiGLU, GQA, a 3:1 interleaving of sliding-window attention (RoPE) and full attention (NoPE), a parallel block, tied input/output embeddings and no biases (p. 3). Hyperparameters are tuned with µP on small models (p. 4). Training runs in FP8 matmuls with a BF16 phase, in a JAX framework on H100s (p. 4). The report says it saw no FP8 instability, and that a fully FP8 run gave a small downstream degradation, which was mitigated by first running some steps in BF16 (p. 4).
- Not disclosed: parameter count details beyond "111B" (p. 1), layer and width, vocabulary size, pre-training token count, data mixture proportions, and the number of sliding-window and full-attention layers. Pre-training data is described only qualitatively: web, code, synthetic, vendor and human-annotated data, with educational samples upweighted (p. 3). There are no pre-training ablation numbers.
- Cooldown: the learning rate is annealed linearly from 2.5 × 10 -4 to 1 × 10 -6 over 50,000 steps. Context is 8k for the first 30,000 steps, then 32k, 128k and 256k for 10,000, 5,000 and 5,000 steps (p. 5).
- Post-training: alternates centralised and decentralised stages (p. 5). An Instruct model is trained first, then six SFT experts (Code, Safety, RAG, Math, Multilingual, long-context) are merged into an SFT soup. Six RL experts are trained on the soup and merged into an RL soup, followed by a "polishing" phase of best-of-N SFT and ping-pong offline preference (SRPO) and online RLHF (CoPG) (p. 5–6, 17). The report claims this is the "first large-scale attempt" at parallel expert tracks with merging (p. 5); no comparison against a single-track pipeline is given.
- Merging: linear weight averaging with manually and brute-force searched weights. SLERP and task vectors were tried and gave "no significant performance improvements" (p. 16). Experts start from a common instruction model so that special-token embeddings and long-context ability are preserved, and leave-one-out merges are used to find collisions (p. 16). Merging preserves expert performance with "only a 1.8% average drop", with most metrics within 2.5% of the best expert (p. 34, Figure 12). The figure data is not extracted; code is the least well preserved. A few low-LR SFT steps on the merged model reach or exceed 100% of expert performance on many metrics (p. 35). The model was informed by 500 evaluation metrics (p. 16).
- Algorithms: SRPO, a min-max self-improving preference objective (Choi et al., 2025), is reported to perform best among SLiC, IPO, DPO and SRPO for instruction following, with no numbers shown (p. 9). CoPG (Flet-Berliac et al., 2024) is used offline and online on-policy (p. 7). The reward model scores 92.7% on RewardBench and an average of 72.3% on RMB (p. 7).
- Data and training claims given without numbers: synthetic math data outperforms human-written data (p. 13). Synthetic code data helps only small models and gives negligible gains for larger ones (p. 11). Multilingual best-of-N output is "comparable or even better" than human gold labels (p. 10). The polishing phase is credited with the largest effect on safety and helpfulness (p. 14).
- Efficiency claims: a serving footprint of two A100s or H100s, and up to 156 tokens/sec, "1.75x higher than GPT-4o and 2.4x higher than DeepSeek V3" (p. 1). The conditions for the throughput comparison are not given. KV cache at 8k is 75% of Llama 3.3 70B Instruct, 23.8% of Llama 3.1 405B Instruct and 45.5% of Mistral Large (p. 34).
- Headline table (p. 2, Table 1): Command A scores MMLU 85.5 (DeepSeek V3 88.5, GPT-4o 85.7, Llama 3.3 70B 86.0), MATH 80.0 (Llama 3.3 70B 77.0, DeepSeek V3 70.2), IFEval 90.9 (Llama 3.3 70B 92.1), GPQA 50.8 (DeepSeek V3 59.1), Taubench 51.7 (GPT-4o 51.2, DeepSeek V3 39.1), BFCL 63.8 (GPT-4o 72.1). Command A is not best on MMLU, IFEval, GPQA or BFCL in this table. Table 3 on p. 18 gives a different MMLU for GPT-4o (89.2) than Table 1 (85.7); the report does not explain this.
- Academic (p. 18, Table 3): MMLU-Pro 69.6 against GPT-4o 77.9, DeepSeek V3 75.9, Claude 3.5 Sonnet 78.0 and Gemini 2.0 Pro 79.1. InFoBench 94.9 against GPT-4o 94.0. IFEval scores are averaged over prompt- and instruction-level strict accuracy for most models, but not for DeepSeek V3, whose number is prompt-level only (p. 18, footnote to Table 3), so the comparison is not like for like.
- Agents (p. 19, Tables 4–6): Taubench Retail P@1 60.0 against GPT-4o 60.6 and Claude 3.5 Sonnet 69.2. Airline P@1 45.3 against GPT-4o 43.0 and Claude 3.5 Sonnet 46.0. Taubench scores are "aggregated over 10 runs" (p. 19). BFCL Overall is 63.8 against GPT-4o 72.1 and Qwen 2.5 72B Instruct 63.5 (p. 19, Table 5). BFCL numbers come from the independently run leaderboard, taking "the larger" of function-calling and prompted scores. Command A's Multi-turn is 25.5, against 47.6 for GPT-4o and 48.4 for Claude 3.7 Sonnet. RAG (p. 19, Table 4): ChatRAGBench 72.9 against GPT-4o 66.6; StrategyQA 76.7 against GPT-4o 81.2.
- Multilingual (p. 20–23): NTREX COMET-20 average 68.8 against GPT-4o 71.0 (p. 20, Table 7; table partly garbled). mArenaHard LLM-judge win rates average 78.9 against Llama 3.3 70B Instruct, 78.7 against Llama 3.1 405B Instruct, 65.9 against Mistral Large 2 and 53.4 against DeepSeek V3 (p. 20, Table 8, also garbled). Human evaluation uses 100 translated prompts across 9 languages (p. 20, Figure 5). Command A's Language Confusion LPR average is 93.0 against Command R+ Refresh 95.5 (p. 23, Table 10). The text says Command A has the highest aggregate, but Command R+ Refresh scores higher, so the text conflicts with the table. ADI2 Arabic dialect adherence is 24.2 monolingual and 33.5 crosslingual against Gemini 1.5 Pro 19.3 and 26.4 (p. 23, Table 11).
- Code (p. 24–25): all baselines are internal reproductions except where marked. Command A scores MBPP+ 86.2, LiveCodeBench 26.9, BigCodeBench 45.4 and RepoQA 92.6 against DeepSeek V3 90.0, 33.5, 50.0 / 48.6 and 92.2 (p. 24, Table 12). The agentic variant, with execution feedback from unit tests, reaches LiveCodeBench 32.9 and BigCodeBench 59.7. The report states gains of "+5.9%" for LiveCodeBench, "+14.3%" for BigCodeBench and "+12.3%" for LBPP (p. 24); the BigCodeBench agent number comes with a 3-test split rather than the standard protocol. SWE-Bench Verified 26.8 against DeepSeek V3 42.0 / 45.8; Aider Polyglot 14.7 against 49.6 / 51.6 (p. 24, Table 13). The report says code editing was not targeted. SQL (p. 25, Table 14): Spider Dev 79.5 for Command A against Qwen 2.5 72B Instruct 83.5 and Llama 3.1 405B Instruct 83.0, yet the text says Command A "leads in both Spider Dev, and Bird". The Spider Dev claim is contradicted by the table. Bird Dev is 59.5 against Llama 3.1 405B Instruct 59.4. The internal SQL average is 55.3 against DeepSeek V3 60.8. Internal benchmarks are not released.
- Math and reasoning (p. 26, Table 15): MATH 80.0 against GPT-4o 68.5 and Llama 3.3 70B 77.0. AIME 2024 is 23.3 against GPT-4o 9.3. GPQA Diamond is 50.8 against GPT-4o 46.0. External figures are taken from officially reported sources, or are internal evaluations where marked *. GPT-4o's GPQA is 53.6 in Table 1 (p. 2) and Table 3 (p. 18) but 46.0 in Table 15 (p. 26). No settings are given for MATH or AIME (sampling, number of samples).
- Safety (p. 27–31): absolute default safety is 70.4, third among large models after Claude 3.5 Sonnet (80.0) and Qwen 2.5 72B (71.4) (p. 29, Table 16). Relative safety winrate vs Command A is 49.5 for Command R7B against 26.6 for GPT-4o. Over-refusal on XSTest is 1.1 in total (p. 30, Table 17), but Command A's internal over-refusal is 7.1, against 1.2 for DeepSeek V3. The internal over-refusal set was built by red-teaming Command R+ Refresh (p. 27, footnote 9). The relative-safety jury has 77.7% human agreement and Cohen's Kappa of 0.55 (p. 27). Demographic fairness: Command A fails about 1% of race-invariance tests and none on gender (p. 28, Figure 8, as text).
- Enterprise benchmarks (p. 32–34): internal, unreleased and LLM-judged. Generative pass rate over 22 tasks is 94.2 against Command R+ Refresh 87.4, Claude 3.5 Sonnet v2 84.2 and GPT-4o 79.1 (p. 33, Table 18). RAG Llama Index Correctness average is 4.73 against Claude 3.5 Sonnet v2 4.72 (p. 33, Table 19), a margin of 0.01 on a 1–5 scale. Answerable accuracy is 96 against GPT-4o 94, and unanswerable accuracy is 91 against Command R+ Refresh 95 (p. 33, Table 20).
- Long context (p. 34, Tables 21–22): RULER at 128k is 90.0 against Claude 3.5 Sonnet (10-22) 93.8 and Gemini-1.5-Pro (002) 91.7; at 256k it is 84.6 against Gemini-1.5-Pro 91.6. LongBench-V2 overall is 43.4 against GPT-4o (11-20) 46.0 and Claude 3.5 Sonnet (10-22) 40.7.
- Human evaluation (p. 36–38, Table 23): about 800 internal prompts (350 general, 150 reasoning, 300 code), authored by Cohere's annotators and filtered with Command R+ Refresh. Command A win rate versus GPT-4o is 50.4 general, 51.4 reasoning and 46.8 code; versus GPT-4.5 Preview 47.2, 30.7 and 38.3; versus DeepSeek V3 49.0, 49.3 and 54.7; versus Llama 3.3 70B Instruct 68.8, 71.7 and 63.4. No confidence intervals are reported. Polishing raised the win rate against GPT-4o from 43.2 to 50.4 on general, 41.4 to 51.4 on reasoning and 30.0 to 46.8 on code (p. 37). This is the one pre/post comparison of a pipeline stage with numbers.
- Evidence summary: the authors built and evaluated the model; the human evaluation set was built by them, and the main enterprise benchmarks are internal. Several baselines are internal reproductions, and baselines differ across tables (see the GPT-4o numbers above). There are no ablations for architecture or for merging versus a single track, and no seeds or variance are reported apart from the Taubench run counts. Weights are released under CC-BY-NC with an acceptable use addendum (p. 2), but not data or training code.

## Related

- Llama 3 (Dubey et al., 2024): the report contrasts its sequential single-model post-training with Command A's parallel experts and merging, and borrows reward-model sample refinement from it; Llama 3.3 70B and Llama 3.1 405B are main baselines.
- DeepSeek V3: the strongest open baseline; it beats Command A on MMLU, GPQA, SWE-Bench, Aider and the internal SQL average, and it is roughly tied on human evaluation.
- GPT-4o, Claude 3.5/3.7 Sonnet, Gemini 1.5/2.0: closed baselines; they lead on MMLU-Pro, BFCL, long-context at 128k and above, and the safety score for Claude.
- Gemma 2 / Gemma 3 style recipes and WARP (Ramé et al., 2024): the weight-averaging line of work that the merging and the RL-to-parent merge build on.
- SRPO (Choi et al., 2025) and CoPG (Flet-Berliac et al., 2024): Cohere's own algorithms, used here with no stand-alone ablation in this report.
- Yang et al. (2025) (interleaved RoPE/NoPE attention): the cited source for the hybrid attention layout, which the report credits with lower KV cache use.
- Command R+ Refresh / Command R7B: Cohere's previous generation and the small sibling; used as internal baselines and as data filters and judges.
- τ-bench (Yao et al., 2024), BFCL, RULER, LongBench-V2, Language Confusion Benchmark, mArenaHard: the external evaluation suites used.
